## 单卡前向进展探针

探针循环执行矩阵乘与 `cuda` 设备同步，以 gap 大于等于 200 ms 为事件。64 卡 1 小时轮次覆盖 230,400 卡秒、约 19.9 亿次同步：

| 轮次 | 规模与时长 | 事件数 | 命中卡 | 事件率 | P50 / max |
| --- | --- | ---: | ---: | ---: | --- |
| long | 64 卡 x 1 h | 40 | 6/64 | 0.0104 次/卡/min | 212.6 / 272.3 ms |
| repeat | 64 卡 x 20 min | 15 | 4/64 | 0.0117 次/卡/min | 211 / 228 ms |

长轮次中没有大于等于 300 ms 或 500 ms 的事件，75% 的事件集中在两张卡。节点排名较稳定但命中的设备序号变化，提示主机/节点级因素，尚不足以定位永久硬件故障。相同探针的 25 张 NVIDIA 卡 x 20 min 对照为零事件，对应 95% 单侧上界约 0.006 次/卡/min；由于平台、主机和样本量不同，该对照只说明量级，不作为硬件排名。

## direct dispatch 说明

厂商材料把非 direct 模式描述为每个 stream 额外使用 CPU 线程排队和派发，并存在更频繁的 CPU/GPU 同步；CPU 负载或锁竞争可能使信号等待暴露为 Stall。`MACA_DIRECT_DISPATCH=1` 改由用户线程直接派发，来源在一组 Hygon C86-7491 + C550 环境中没有复现 Stall。

这支持“派发路径会改变 Stall 概率”，但材料没有披露卡数、观察时长、同步次数和置信上界，因此状态是**厂商归因与缓解方向已记录，独立因果闭环待补**。来源还建议对大量小 kernel 使用 CUDA Graph，并称后续 MXMACA 版本将默认 direct dispatch；版本行为必须以实际部署版本复核。

## 独立的大规模通信尾延迟

另一集群的 256 MiB AllReduce 文档级扫描显示：

| 规模 | 干净轮次带宽 | 异常现象 |
| ---: | ---: | --- |
| 256 卡 | 大于 60 GB/s | 3 次重复中部分轮次出现长尾 |
| 512 卡 | 约 50 GB/s | 5 次重复中部分轮次出现长尾，P99 最高 1,043 ms |

约 20%--60% 的重复轮命中尾延迟。增加 QP 没有改善：256 卡从 QP1 的 63.3 GB/s 降至 QP32 的 19.4 GB/s；512 卡从 QP1 的 49.7 GB/s 降至 QP16 的 29.1 GB/s。256 卡退出阶段还出现 `destroy_process_group` SIGSEGV。

该通信现象发生在不同集群，且共享网络负载、交换机 counter 和多租户状态不可见，不能与 200--272 ms 单卡 Stall 合并为同一根因。它只支持“规模、QP 和外部网络状态需要独立复测”的结论。

## 结论边界

- C550 单卡探针的事件率比 A3 材料低一个数量级以上，且没有半秒级事件；两边软硬件条件不同，不作芯片优劣结论。
- direct dispatch 是有方向性的缓解证据，不是给定观察时长下的零事件率证明。
- 256/512 卡 AllReduce 尾延迟和 QP 退化属于通信域问题；缺少网络遥测时不能归因到卡、NIC、交换机或外部竞争中的某一项。
- 训练前应分别运行零通信前向进展探针、同 cohort collective 复测和真实 Megatron 通信组检查，三者不能相互替代。
