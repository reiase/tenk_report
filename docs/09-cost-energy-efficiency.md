# 成本、能耗与资源效率

## 核算模型

万卡训练资源效率以有效训练卡时为核心，统一纳入计算、网络、存储、健康检查、故障恢复和观测开销。

\[
C_{\text{total}} =
C_{\text{compute}} +
C_{\text{network}} +
C_{\text{storage}} +
C_{\text{health}} +
C_{\text{recovery}} +
C_{\text{observe}}
\]

其中，计算成本按设备数量与占用时间计量，健康检查和观测成本单独记录，便于比较不同准入与采样策略的工程收益。

有效训练卡时定义为：

\[
H_{\text{effective}} =
N_{\text{device}} \times
T_{\text{train}} \times
R_{\text{forward-progress}}
\]

资源效率定义为有效训练卡时与总分配卡时之比：

\[
\eta_{\text{resource}} =
\frac{H_{\text{effective}}}
{H_{\text{allocated}}}
\]

## 已量化效率指标

| 指标 | 结果 | 资源效率含义 |
| --- | ---: | --- |
| A3 1,024→4,096 卡弱扩展 | 94.26% | 4 倍规模保持 94.26% 单卡吞吐 |
| 万卡协同加权 ECP | 92.43% | 两类资源池共同窗口保持 92.43% 基线算力 |
| 健康检查墙钟 | 1,706→1,056 秒 | 单轮减少 650 秒，下降 38.1% |
| 健康检查卡时 | 约减少 184.9 加速卡时/轮 | 1,024 ranks × 650 秒折算 |
| 4,096 卡 Dense 稳定性 | CV 1.68% | 降低跨 step 波动与尾部等待 |
| 工程快照 | 约 2.6 GB | 训练脚本、配置与聚合结果压缩归档 |
| 大对象资产清单 | 约 22 TB + 84 GB profiler | checkpoint、权重、派生数据和 profile 分层管理 |

健康检查运行时优化释放的卡时可直接用于训练、复测或资源周转。以 1,024 ranks 的 64 节点流水线计算，每执行一轮可节省约 184.9 加速卡时；批量扩容和周期巡检时，收益随执行次数线性累积。

## 训练资源效率

Dense 与 MoE 采用不同的效率指标组合：

| 工作负载 | 主要指标 | 配套指标 |
| --- | --- | --- |
| Dense | TFLOPS/GPU、MFU、弱扩展效率 | step time、CV、通信暴露比例 |
| MoE | samples/s、tokens/s、TFLOPS/GPU | All-to-All、专家负载、padding、CPU offload |
| 协同训练 | 分资源池 ECP、加权 ECP | 参数同步周期、组间进度与共同窗口 |
| 健康准入 | 目标集合通过率、检查墙钟 | 复测次数、卡时、控制面等待 |

MoE 的资源效率同时记录 router、permutation、padding、All-to-All 和 CPU offload。该组合能够解释专家模型中计算 FLOPs、通信成本和主机资源之间的转换关系。

## 能耗模型

训练能耗按设备、主机、网络和存储四部分统计：

\[
E_{\text{job}} =
\int_0^T
\left(
P_{\text{device}}(t) +
P_{\text{host}}(t) +
P_{\text{network}}(t) +
P_{\text{storage}}(t)
\right) dt
\]

机房级能耗使用 PUE 折算：

\[
E_{\text{facility}} = E_{\text{IT}} \times \text{PUE}
\]

单次训练报告同步记录平均功率、P95 功率、训练墙钟、有效 token 数和检查点写入量，形成 `kWh/10^12 tokens`、`kWh/step` 和 `kWh/checkpoint` 三类可比指标。

## 存储与归档效率

训练资产采用三层结构：

1. **高频运行层**：本地热库、短期日志和环形缓冲，服务当前作业。
2. **实验归档层**：配置、聚合结果、脚本、Git bundle 和 SHA256，服务复现与评审。
3. **大对象层**：checkpoint、权重、派生数据和 profiler 原件，按对象清单与生命周期管理。

成功样本采用预注册比例保留，异常窗口保存更高分辨率；节点/作业聚合减少万 rank 原始事件的长期存储量。EXP-014 的工程快照完成 10 个 tar、6 个 Git bundle 和 75 项 SHA256 校验，形成可恢复的配置与代码资产集合。

## 优化杠杆

| 优化方向 | 作用机制 | 评价指标 |
| --- | --- | --- |
| 健康准入前置 | 减少慢卡、坏卡和异常链路进入训练 | 有效训练时间、失败重启卡时 |
| 拓扑感知放置 | 缩短高频通信路径并均衡跨域出口 | 通信暴露比例、扩展效率 |
| TP/PP 联合搜索 | 平衡算子效率、流水线气泡和通信 | MFU、step time、显存 |
| 控制面本地热库 | 降低共享文件系统锁等待 | 健康检查墙钟 |
| 分层观测 | 常驻轻量、异常窗口深挖 | 观测开销、定位时间 |
| 增量归档 | 降低重复传输与存储 | 归档字节、恢复时间 |

成本、能耗与资源效率最终统一到“每单位有效训练产出”的评价框架，使性能提升能够转化为可量化的卡时、能耗和运维收益。
