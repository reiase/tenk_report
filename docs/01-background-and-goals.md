# 项目背景与建设目标

## 项目背景

大模型训练从千卡扩展到万卡后，性能问题由单卡算力逐步转化为资源质量、并行策略、通信拓扑、调度放置、前向进展和故障恢复的系统性问题。任何慢卡、异常链路、通信组错位或控制面长尾，都会通过同步训练的尾部效应放大为全局等待。

本项目建设 8,192 张华为 Atlas 900 A3 与 2,048 张沐曦曦云 C550 两个国产加速卡资源池，总纳管规模 10,240 张。两类硬件分别采用灵衢/HCCL 与 MetaXLink/MCCL 通信体系，并在统一的资产、调度、实验和指标框架下协同运行。

## 建设目标

- 建立覆盖 10,240 张加速卡的统一资产与健康状态管理体系。
- 建立 A3 与 C550 分资源池健康基线，完成设备、节点、链路和训练拓扑的分层准入。
- 完成 Megatron 在两套国产软硬件栈上的模型适配、并行策略调优和通信优化。
- 建立从单节点、千卡到目标规模的渐进式扩容方法，以扩展效率和稳定性驱动放量。
- 建立训练、通信、设备和系统事件的统一观测坐标，提升慢卡、通信长尾和 Stall 的定位效率。
- 形成可复现的实验记录、配置快照、统计窗口和工程资产校验体系。

## 技术挑战

| 挑战 | 万卡场景影响 | 技术路线 |
| --- | --- | --- |
| 异构软硬件栈 | 算子、通信、显存和故障语义存在差异 | 统一控制面、分资源池适配与评价 |
| 资源质量长尾 | 单卡或单链路异常放大全局同步等待 | 分层筛查、冻结复测、精确节点准入 |
| 并行组合空间大 | TP/PP/DP/EP/VPP 相互耦合 | 容量约束、网格搜索、方案级复核 |
| 跨域通信增长 | 小消息时延、拥塞和尾部等待上升 | 拓扑感知放置、rank 映射、通信消融 |
| 前向进展异常 | 主机、运行时与设备等待相互叠加 | 同步探针、设备事件、系统 trace 联合定位 |
| 规模化验证成本 | 全量 profiler 与集中日志开销过高 | 本地聚合、确定性采样、异常窗口下钻 |

## 建设范围

项目技术体系覆盖以下五个层次：

1. **资源层**：加速卡、服务器、超节点、网络、存储和故障域。
2. **平台层**：资产管理、调度编排、健康检查、镜像与软件物料管理。
3. **训练层**：Megatron 模型构建、并行组、优化器、重计算、通信重叠与检查点。
4. **观测层**：step、rank、module、collective、设备事件、系统事件和网络计数器。
5. **评价层**：稳态吞吐、MFU、扩展效率、协同 ECP、功能运行、拓扑通过率和健康检查效率。

协同训练以 8 个训练组和 64 个参数服务器组织。A3 与 C550 在各自通信域内执行模型训练，控制面统一管理资源状态、运行进度和周期参数同步。

## 评价体系

| 维度 | 核心指标 | 评价方式 |
| --- | --- | --- |
| 资源规模 | 纳管卡数、候选池覆盖、目标节点集合 | 资产清单、筛查结果与调度快照 |
| 健康准入 | correctness、SDC、HBM、集合通信与拓扑状态 | 静态检查、动态测试、成对复测、Final topology |
| 训练性能 | TFLOPS/GPU、step time、MFU、CV | 冻结配置后的稳态窗口 |
| 规模扩展 | 总吞吐加速比、弱扩展效率、ECP 保留率 | 同模型同口径基线与目标规模对比 |
| 稳定性 | 前向进展事件、超时、失败阶段、恢复结果 | 同步探针、训练日志、系统 trace 与复测 |
| 工程效率 | 健康检查墙钟、卡时消耗、资产完整性 | 阶段耗时、资源占用与校验清单 |

这一评价体系将资源质量、训练能力和工程运行效率纳入同一技术闭环，为后续模型扩展和持续运维提供统一基线。
