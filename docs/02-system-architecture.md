# 系统总体架构

## 设计原则

- **异构分池**：A3 与 C550 维护独立运行镜像、通信域、健康基线和性能曲线。
- **统一控制**：资产、调度、实验编号、指标定义和故障处置流程统一管理。
- **拓扑感知**：资源分配遵循卡内、节点内、超节点内和跨超节点的通信层级。
- **健康先行**：资源通过分层健康准入后进入训练拓扑和性能验证。
- **逐级扩展**：从单节点、小规模、中等规模逐步放大到目标规模。
- **全程可追溯**：训练结果与配置、成员、拓扑、日志和软件版本建立稳定关联。

## 逻辑架构

![训练系统逻辑架构](assets/diagrams/system-logical-architecture.svg){ .technical-diagram loading=lazy }

系统由统一控制面、A3 训练数据面、C550 训练数据面和分层观测面组成。控制面负责资源状态、作业编排和实验管理；两个训练数据面分别运行 Megatron 与集合通信；观测面以统一训练坐标汇聚性能、通信和稳定性信息。

## 资源组织

| 层级 | A3 资源池 | C550 资源池 |
| --- | --- | --- |
| 项目规模 | 8,192 张加速卡 | 2,048 张加速卡 |
| 基础 scale-up 域 | 灵衢逻辑超节点，最大 384 NPU | MetaXLink 8 卡全互连 |
| 协同验收编排 | 4 个 2,048 卡训练组 | 4 个 512 卡训练组 |
| 集合通信 | HCCL | MCCL/Torch distributed |
| 主要优化对象 | 超节点亲和、HCCL 路径、TP/PP/DP | 节点筛查、MCCL 通信、direct dispatch |
| 统一接口 | 资产状态、实验元数据、训练坐标、指标与故障状态 | 资产状态、实验元数据、训练坐标、指标与故障状态 |

物理资源按照“加速卡—服务器—scale-up 域—scale-out 网络—资源池”五级组织。调度快照将 `resource_pool`、`fault_domain`、`node`、`rank` 和 `device_id` 固化到每次实验，从而把训练性能、集合通信和故障事件准确映射到物理位置。

## 控制面与数据面

控制面承担四类职责：

1. **资源管理**：维护设备、节点、故障域、健康状态和可调度集合。
2. **作业编排**：完成训练组创建、拓扑感知放置、会合信息下发和生命周期控制。
3. **实验治理**：记录模型、并行配置、软件版本、统计窗口和实验编号。
4. **状态闭环**：关联健康检查、训练异常、隔离处置、维修和回池复验。

A3 与 C550 数据面分别完成数据读取、模型训练、梯度通信和检查点写入。协同场景由 8 个训练组和 64 个参数服务器构成，各训练组保持独立的 Megatron 并行域，参数服务器按配置周期聚合模型状态。

## 观测数据面

观测系统采用“公共训练语义 + 厂商原生适配”结构：

| 层次 | 统一对象 | 主要作用 |
| --- | --- | --- |
| 训练层 | step、micro-step、module、optimizer | 识别阶段耗时与计算负载 |
| 分布式层 | rank、TP/PP/DP/EP 角色、collective | 识别并行组与通信等待 |
| 设备层 | stream、event、显存、功耗、温度 | 识别设备执行和资源状态 |
| 通信层 | HCCL/MCCL task、NIC/交换机 counter | 识别链路、算法与拥塞 |
| 系统层 | CPU、IRQ、调度、文件系统 | 识别主机侧前向进展与控制面长尾 |

高频数据在 rank 或节点本地完成过滤和聚合，跨节点传输分位数、Top-K、异常集合与窄时间窗事件。该方式将常驻观测开销控制在固定预算内，并支持从作业概览逐级下钻到具体 rank、collective、kernel 和系统调用路径。

## 三条核心工程链路

### 资源准入链

`资产对账 → 静态检查 → 单卡计算与 HBM → 成对通信 → 精确节点选择 → 训练拓扑验收`

该链路将 correctness、SDC、HBM、慢卡、竞争状态和通信异常分型处理，形成可调度训练集合。

### 性能扩展链

`单节点基线 → 千卡配置搜索 → 通信与重计算消融 → 中等规模复核 → 目标规模启动与训练`

每一级均固化模型、并行组合、批大小、软件版本和成员拓扑，以稳态吞吐、MFU、扩展效率和稳定性评价放量效果。

### 故障闭环链

`异常检测 → 作业/节点/rank 定位 → module/collective 分析 → 设备与系统事件关联 → 修正 → 同条件复验`

该链路已用于 A3 Stall、Gloo 建组、C550 通信尾延迟、HBM SLOW 和健康检查控制面长尾等问题。

## 关键架构取舍

- 双资源池保持独立性能基线，协同层使用加权 ECP 与参数同步评价整体运行。
- 训练高频通信组优先映射到近距离互连域，跨域数据并行保持对称分布。
- 健康检查与真实训练拓扑互补：前者完成资源筛查，后者验证实际并行组。
- 常驻轻量观测与短窗口深度采集分层部署，兼顾覆盖范围与诊断精度。
- 调度映射、rank 分组和通信拓扑随实验归档，保证扩展结果能够回到实际资源集合。
