# 执行摘要

## 研究对象与范围

本报告面向总规模为 10,240 张国产加速器的大模型训练基础设施，其中华为 Atlas 900 A3 SuperPoD 资源池包含 8,192 张加速器，沐曦曦云 C550 资源池包含 2,048 张 GPU。两类资源具有不同的器件形态、互连层级和软件栈，因此分别建立训练资源准入、Megatron 适配和扩展效率证据，再通过统一的实验坐标、状态语义与指标体系进行管理。

“万卡规模”指两个资源池的可纳管设备总数，不表示 10,240 张异构设备共同执行同一个同步训练作业。部署规模、可分配规模、满足当前准入条件的规模和单作业实际参与规模属于不同统计量，须在结果章节分别披露。

## 主要认识与证据状态

本报告形成以下六项主要认识：

1. 训练资源健康由正确性、可持续能力和前向进展三个证据面共同构成。峰值算力、HBM 带宽或 ECC 状态均不能单独覆盖这一判定空间。
2. 同步训练会放大局部长尾。一个 rank 的完成等待进入 barrier 或 collective 关键路径后，会转化为整个同步组的空等资源时间，并进一步影响 MFU、检查点进度和作业完工时间。
3. A3 与 C550 材料均在 Host—runtime—驱动—设备完成链上观察到额外等待，但其时间分布、空间结构和软件敏感性不同。两类平台可以共享测量框架，不应共享事件率或底层根因。
4. A3 固定资源池对照显示，单卡事件排序与训练 step 时间存在样本内关联，但关联方向随 DP、Dense 和 MoE 负载变化。该结果支持按训练负载验证资源特征，不支持跨工作负载的静态选择公式。
5. 万 rank 观测需要采用本地低密度事实、角色条件基线、联邦查询和触发式深度取证；分布式火焰图、变量状态、通信进行中快照与崩溃上下文共享 rank/step/role 坐标，而覆盖、丢弃、扰动和 partial 状态属于结论的一部分。
6. 训练岛和低频 outer synchronization 提供了放松跨故障域全局同步的研究路径。DiLoCo 与 Parameter Server 的组合在本报告中属于架构综合，尚不构成目标资源池的生产训练结论。

上述认识具有不同证据成熟度。公开规格用于约束能力上界；内部汇总用于建立问题模型；项目级生产结论仍需绑定原始事件、冻结配置、目标拓扑与重复实验。

## 报告形成的技术框架

- 面向两种国产加速器构建统一控制、分池优化的万卡训练架构。
- 建立覆盖静态事实、计算与存储正确性、稳态能力、前向进展、通信路径和训练拓扑的资源准入证据链。
- 形成 Megatron 在不同硬件栈上的分层调优路径与可复现实验记录。
- 建立以扩展效率和稳定性门限驱动的逐级规模验证方法。
- 建立低成本常驻观测、异常窗口下钻和质量收据相结合的分布式诊断模型。

## 限制与适用范围

当前报告尚未完整写入硬件批次、实际组网、模型配置和生产软件版本。A3/C550 停顿材料属于内部汇总，逐事件数据、完整配置和完整性摘要待导入，因此事件率对应的是已记录的卡池、版本和负载。C550 的大规模通信尾部来自另一集群，后续结合网络侧证据分析设备、通信库与 fabric 的贡献。两个资源池按各自软件栈和训练作业讨论，不做缺少同口径实验的跨硬件性能排名。低通信弹性训练需要另行验证模型质量、总计算、版本一致性和故障恢复，不能从公开研究直接外推到本项目。
