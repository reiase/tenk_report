# 加速卡与软件栈

## 硬件规格与部署形态

项目采用华为 Atlas 900 A3 SuperPoD 和沐曦曦云 C550 两类训练硬件。公开产品规格用于描述基础能力，项目训练指标采用对应资源池的实测结果。

| 资源池 | 项目规模 | 产品形态 | 内存能力 | scale-up 互连 | 来源 |
| --- | ---: | --- | --- | --- | --- |
| Atlas 900 A3 SuperPoD | 8,192 张 | 最大 12 个计算柜与 4 个总线设备柜 | 最大 128 GB/NPU，整套最大 48 TB | 灵衢，最大 384 NPU；D2D 双向 784 GB/s | [R001](references.md#r001) |
| 曦云 C550 | 2,048 张 | OAM 1.5/2.0 模组，最大板卡功耗 450 W | 64 GB/卡，全链路 ECC | MetaXLink 8 卡全互连，公开带宽最高 896 GB/s | [R002](references.md#r002) |

### Atlas 900 A3 SuperPoD

Atlas 900 A3 通过灵衢互连将最多 384 张 NPU 组织为逻辑超节点，公开配置包含最大 192 颗鲲鹏 920 CPU、48 TB 片上内存和 1:1 无收敛总线能力。项目在超节点内部优先部署高频 TP 通信，在跨超节点层承载 DP 与规模扩展流量，并通过 HCCL rank 映射保持通信域对称。

### 曦云 C550

C550 采用 64 GB 高带宽显存和全链路 ECC，节点内通过 MetaXLink 构建 8 卡全互连，MXMACA 软件栈提供训练框架与通信适配。项目围绕节点筛查、MCCL 集合通信、前向进展探针和大规模拓扑验收建立独立基线。

## 性能与功耗基线

硬件性能采用三层指标描述：

| 层次 | 指标 | 用途 |
| --- | --- | --- |
| 产品能力 | 理论算力、内存带宽、互连带宽、功耗上限 | 容量规划与合理性校验 |
| 设备基线 | GEMM、HBM 有效带宽、稳态功耗、温度 | 同型号同版本设备筛查 |
| 训练性能 | TFLOPS/GPU、step time、MFU、扩展效率 | 模型与并行方案评价 |

设备筛查在同一后端、硬件型号、驱动和固件组成的 cohort 内建立中位数和分位数。瞬时计算、HBM 带宽和稳态计算联合识别性能偏离；功耗、温度、时钟和限频状态用于区分功耗墙、散热限制与设备性能异常。

C550 候选池的有效 HBM 中位数为 1,488.66 GB/s，70 张 HBM SLOW 设备集中在 1,045.05--1,054.11 GB/s 区间，中位数 1,050.28 GB/s，为同轮有效中位数的 70.6%。该同批次分布为资源筛查提供了稳定的相对基线。

## 软件栈

| 层级 | A3 资源池 | C550 资源池 | 配置管理 |
| --- | --- | --- | --- |
| 设备运行时 | Ascend 驱动与 CANN | MXMACA 驱动与运行时 | 版本、补丁、设备能力快照 |
| 集合通信 | HCCL | MCCL / Torch distributed | 算法、超时、环境变量与拓扑 |
| 框架 | PyTorch + Megatron/MindSpeed | PyTorch + Megatron 适配 | 代码 commit 与补丁摘要 |
| 容器环境 | A3 训练镜像 | C550 训练镜像 | 不可变镜像摘要 |
| 模型配置 | Qwen3-200B Dense、Qwen3-1T MoE | 对应训练组模型配置 | 参数枚举、精度、并行与批大小 |
| 观测适配 | HCCL 原生事件 + Torch 公共层 | Torch 公共层 + MCCL 能力接口 | 能力探测与字段契约 |

软件物料清单与实验编号绑定，记录固件、驱动、通信库、框架、容器镜像、模型代码和关键环境变量。控制面配置与训练运行配置分别保存，最终以实际启动参数和运行时能力快照构成实验基线。

### 健康检查运行基线

| 字段 | A3 | C550 |
| --- | --- | --- |
| 设备标识 | `ascend` | `metax` |
| PyTorch distributed backend | `hccl` | `nccl` |
| 底层通信 runtime | `hccl` | `mccl` |
| 典型单节点 rank 数 | 16 | 8 |
| 动态检查精度 | BF16 | BF16 |
| 多节点验收 | HCCL 训练通信组 | MCCL Scale8--Final256 |

健康检查使用严格配置 schema 管理超时、检测矩阵、分组算法、拓扑定义、结果保留和判定门限。准备、激活、运行和结果回收分别计时，确保设备执行、控制面等待和证据传输具有独立时间语义。

## 算子与精度策略

两类资源池分别确认训练精度、优化器状态精度、通信精度和损失缩放策略。算子优化按矩阵乘、注意力、归一化、词表并行交叉熵和优化器更新的热点顺序推进。

每项融合、重计算或低精度改动依次完成：

1. 固定输入输出一致性校验。
2. 短程 loss 与梯度范数对齐。
3. 显存峰值和 OOM 风险评估。
4. 稳态吞吐与跨 rank 方差测量。
5. 扩展规模下的通信和数值复核。

1T MoE 实验验证了 FP32 main grad 与当前融合反向路径的兼容组合，并通过 EP、重计算和 bucket 消融确定可运行配置。

## 兼容与适配

Megatron 与厂商软件栈之间采用薄适配层。公共层使用 tensor、module、step、rank 和 `torch.distributed` 语义，设备 event、显存接口及 HCCL/MCCL 内部事件由平台插件提供。

兼容性验证覆盖同步与异步 collective、`Work.wait()`、event/stream 计时、显存统计、错误传播、进程模型和 profiler 开关。训练适配进一步覆盖模型构建、优化器、分布式 checkpoint、随机状态恢复、融合算子、并行组创建和长序列内存压力，使功能、性能和恢复能力采用同一版本基线。
