# 复现实验清单

## 目的

复现的目标是在相同的硬件、软件、拓扑、输入、负载和判定规则下得到统计一致的结论。实验记录应描述可迁移的技术条件、方法版本和适用条件，不依赖某次临时执行环境。

## 硬件与环境

- [ ] 资源池、设备型号、硬件批次、节点数和每节点卡数已记录。
- [ ] 逻辑卡、物理卡、节点、机柜和超节点映射完整。
- [ ] CPU、NUMA、内存、存储和网络拓扑已记录。
- [ ] 功率上限、冷却方式、环境温度和机柜供电策略已记录。
- [ ] 固件、驱动、通信库、算子库、框架和模型版本已冻结。
- [ ] 容器或运行环境具有不可变版本标识。
- [ ] 测试前设备空闲，外部进程和显存占用符合预注册条件。

## 配置与输入

- [ ] 保存经过校验的最终实验配置，而不只保存推荐默认值。
- [ ] 同时保存启动模板、环境变量、最终 resolved command、run-config 和各自 SHA256；开关名与人类可读 rank-order 标签建立明确映射。
- [ ] MFU 结果记录模型 FLOPs 公式、理论峰值、训练精度、设备数量与卡/die/逻辑设备单位，以及是否计入重计算。
- [ ] 按 stage 定义的重计算策略同时记录总层数、PP 数和实际重计算层数，不只保存 uniform/block 等策略名。
- [ ] 记录随机种子、数据类型、矩阵规模、缓冲区大小、预热次数和测量轮数。
- [ ] 记录持续压力时长、采样窗口、遥测频率和允许误差。
- [ ] 记录性能 cohort 的构成字段、最小样本量和慢卡门限。
- [ ] 记录 SDC 各目标单元、reference 类型、重复次数和 HBM 实际覆盖率。
- [ ] 训练拓扑检查绑定目标模型的并行组合、rank 顺序、通信组和工作负载形状。
- [ ] 故障注入在正式硬件统计中关闭，并与真实故障数据严格分开。
- [ ] 性能主跑默认关闭固定 profiler；如启用，记录 profile start/end step，并在预注册统计中显式排除受影响窗口。
- [ ] MoE 记录总/激活参数、Top-K、expert 数、EP group、dispatcher、capacity/padding、offload fraction、主梯度 dtype 和融合算子版本。

## 单卡计算与存储可靠性测试原则

### 第一阶段：正确性与性能

- [ ] 使用固定随机输入和独立高精度 golden 检查矩阵计算正确性。
- [ ] 正确性在全部计时轮重复检查，而不是只检查预热后的第一轮。
- [ ] 矩阵算力和 HBM 有效带宽均在充分预热后使用设备侧计时。
- [ ] 主指标使用稳健中心统计，并保留全部逐轮分布和尾部数据。
- [ ] 持续负载足以进入热稳态，并记录稳态前后的算力衰减。
- [ ] shape 扫描只用于描述效率区间，不在缺少标定时直接作为淘汰规则。

### 第二阶段：SDC

- [ ] 矩阵、向量、特殊函数、规约和 HBM 地址空间均有对应检查。
- [ ] 同时使用独立 golden、多轮自一致和条件允许时的跨卡多数表决。
- [ ] HBM 测试覆盖固定常量、交替位、walking-bit 和地址即数据模式。
- [ ] 记录实际分配和检查的 HBM 容量；部分覆盖按实际容量表述。
- [ ] SDC 命中保留首个轮次、偏差幅度、不一致元素数和时间对齐遥测。
- [ ] 命中后使用同参数复测、换槽或换节点以及硬件 RAS 证据完成归因。

### 功耗与热态

- [ ] 功耗、温度、时钟和限频状态与性能窗口在同一时间轴上对齐。
- [ ] 遥测在计时区外采集，且采样开销不会显著干扰测试负载。
- [ ] 报告冷态、升温段、稳态和降载后的性能与功耗变化。
- [ ] 若声称功耗相关 SDC，必须执行受控负载分档和冷热循环。
- [ ] 因功耗墙或热限频未达到目标压力的阴性结果标为低置信度并复测。
- [ ] 最大板卡功耗只作为安全包络，不作为越高越好的性能目标。

## 多节点与训练拓扑

- [ ] 静态、单节点、单卡和 Pairwise 检查覆盖所有候选节点。
- [ ] Pairwise 的同域和跨域路径覆盖、换伙伴轮次及随机种子已记录。
- [ ] 节点异常、链路异常和固定路径异常使用独立证据规则归因。
- [ ] 精确目标节点数不足时记录为阻塞，不以缩小规模冒充通过。
- [ ] 最终验收只在真实 TP、DP、EP 和 PP 通信组中执行。
- [ ] 每类通信组的期望数量、实际数量、rank 覆盖和功能状态完整。
- [ ] 多资源池分别运行、分别标定、分别报告，不合并性能指标。
- [ ] 弱扩展逐项核对卡数、TP/PP/DP/EP、GBS、MBS、microbatches、序列长度、代码版本和统计窗口。
- [ ] 跨材料比较前确认规模单位一致；来源写作 die 时，不在缺少硬件映射的情况下自动换算为卡数。
- [ ] 若验收要求异构加权 ECP，单独登记各平台独立基线、共同墙钟窗口、设备权重与每组步数，并明确它不是单作业扩展效率。
- [ ] 短程 startup pass、稳态性能、长稳通过和端到端验收使用不同状态，不因进入 iteration 自动升级。

## ECC/RAS 实验与证据口径

- [ ] 记录本轮采用告警策略还是严格策略，且策略在结果生成前冻结。
- [ ] ECC 查询成功，必需计数可解析，并覆盖全部可见设备和芯片；缺失不按零处理。
- [ ] 每条观测保留节点、设备、芯片、保护域、当前/累计语义、计数值和事件详情。
- [ ] 复测前后分别保存计数快照，能够判断观察窗口内的增量，而不只比较历史总量。
- [ ] 复测冻结软件版本、功率、温度范围、负载、数据模式、持续时间和目标设备。
- [ ] ECC/RAS 事件与单卡正确性、HBM、长稳、功耗/热态及通信结果按同一时间窗关联。
- [ ] 区分数据正确性、forward progress、性能尾部和证据缺失，避免用单一健康分数抹平故障语义。
- [ ] `RETEST_REQUIRED` 在验证完成前不进入训练候选集合；`OBSERVE_ELIGIBLE` 只参与风险排序。
- [ ] 最终节点集合、风险向量、排除约束和内容摘要均可重建，目标节点数不足时保留 `BLOCKED`。
- [ ] 页面/行修复后记录可见容量、计数基线和剩余修复裕量；无法取得时标为模型输入缺失。

## 数据与统计

- [ ] 每个实验具有唯一标识，并能关联资源池、节点、卡、测试阶段和时间窗口。
- [ ] 原始逐轮结果不可覆盖，聚合结果可以从原始记录重建。
- [ ] 样本数、缺失数、失败数、有效轮数和排除原因同时报告。
- [ ] 中位数、P10/P50/P90、变异系数和尾部异常采用预注册口径。
- [ ] 正确性失败、SDC 命中、性能偏离和遥测缺失分开统计。
- [ ] 首轮候选与冻结条件下的复测结果分开保留。
- [ ] 阻塞、未运行和排除项保留在覆盖率分母中。
- [ ] Stall 事件率同时报告逐卡观察时长、同步次数、gap 阈值、事件宽度分布和零事件上界，不只报告命中卡数。
- [ ] 模型交付记录冻结最终配置并由代码枚举参数量；完成 step、loss、逐步性能、检查点完整性和收敛结论分开验收。
- [ ] 短程扩展同时报告 last5、last10 和预注册稳态全窗；不同窗口差异显著时降级结论，不只挑选较高值。

## 观测与诊断复现

- [ ] 记录观测实现版本、启用的 collector、采样率、缓冲区和持久化配置。
- [ ] `global_step`、micro step、rank 和 TP/PP/DP/EP/CP 角色定义与训练配置一致。
- [ ] 常驻观测、采样重路径、短窗口 profiler 和通信库原生插件分别标识。
- [ ] 确定性采样保存算法版本和种子，并验证各 rank 命中相同 step 集合。
- [ ] 深度采集保存触发原因、目标 rank 集合、起止 step、时间窗和对齐方式。
- [ ] 观测开销使用同作业 shadow 或冻结条件下的 on/off A/B，不只引用组件 benchmark。
- [ ] 前向进展探针冻结同步节奏并保留无 profiler/无插桩控制组；深度采集轮不直接进入事件率基线。
- [ ] ftrace 根因记录 timer/IRQ/tasklet 配对覆盖、buffer 丢失、CPU/IRQ affinity 和系统级修复后的同条件回归。
- [ ] 记录期望/实际 rank 与节点、失败分区、丢弃事件、partial 状态和抽样误差。
- [ ] 跨表关联先在同一 rank 内按 step/role 校验，跨 rank 只归并声明为可归并的统计状态。
- [ ] 时间占用先合并重叠区间；API、设备 event 和原生通信计时分别保留口径。
- [ ] 查询和图表保存过滤条件、聚合公式、rank 集合与时间窗口，可回放到原始证据。

## 证据完整性

- [ ] 最终配置、软件版本、环境摘要、拓扑快照和节点选择依据已归档。
- [ ] 每张卡都能追溯到物理位置、测试条件、逐轮数据和最终状态。
- [ ] 结果传输具有长度与内容完整性校验，传输失败不被解释为测试失败。
- [ ] 汇总表、图表和结论可以由受控的原始证据重新生成。
- [ ] 失败、超时和不完整结果保留足够日志供独立复核。
- [ ] 原始证据的位置、访问策略、保留窗口和完整性标识已登记。
- [ ] 报告中的每个生产数字都有实验编号和评审记录。
- [ ] 只有聚合文档而缺少原始运行时标为 `document_only`，列出缺失字段并禁止与日志级证据混排。
- [ ] 关键 run-config、代表日志、启动器和日志包均登记 SHA256；哈希变化触发重新聚合与评审。
- [ ] 基线至少包含预注册稳态窗口；只用单个最好或最后 iteration 时必须降级结论并安排补跑。
- [ ] 会话型来源记录会话 ID、时间范围、字节数、SHA256、解析行数和失败数；工具输出、助手推断与未执行建议使用不同证据状态。
- [ ] 备份记录快照截止时间、纳入/排除范围、tar/Git bundle/SHA256 结果和存储故障域；快照之后的运行进入独立增量。
- [ ] 跨故障域归档在目标端数量/容量对账、内容校验、归档遍历、Git bundle 验证和抽样恢复全部通过后标记完成；访问凭证保留在受控凭据系统中，排除在仓库、聊天和训练日志之外。

## 故障注入回归

工具或判定规则变更后，应使用软件故障注入验证完整检测链路，至少覆盖数值损坏、NaN/Inf、性能衰减、HBM 位翻转、进程退出、超时、通信初始化失败和结果传输异常。

每种注入必须证明三件事：外层状态符合设计、异常能够定位到预期设备或测试组、关闭注入后同一实验条件恢复正常。故障注入结果用于评价检测能力；生产硬件故障率、健康率和 MTBF 采用独立运行统计。
