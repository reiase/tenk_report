# 结论、限制与研究方向

## 结论

万卡训练中的资源健康同时涉及正确性、可持续能力和前向进展。矩阵吞吐、HBM 带宽与 ECC/RAS 分别覆盖其中一部分，却不能替代长时间完成进展观测；进程存活和高设备利用率同样不能证明训练工作持续完成。A3 与 C550 案例显示，额外等待可以在单卡、零通信条件下暴露，并在 BSP 训练中通过最慢 rank 传播。平台的时间分布和软件敏感性不同，因此适合共享测量框架，不适合共享事件率或底层根因。

规模化诊断依赖稳定坐标和渐进下钻，而非持续收集全部原始事件。rank 本地低密度事实用于发现异常 step 和角色，联邦查询形成带覆盖收据的全局概览；分布式火焰图、Python 变量 watch、通信进行中快照和 fatal error 现场只用于已收窄的对象或明确异常触发。Probing 在本文中作为该方法的参考实现，其有效性由覆盖、观测开销、现场完整性和结论可复核性衡量。

MegaScale、Holmes、FLARE、PyTorch Flight Recorder 与 HTA 已分别证明跨 rank 热力图、关系化异常定位、低开销全栈 tracing、collective 现场和离线分布式 trace 分析的工程价值。[R022](references.md#r022) [R023](references.md#r023) [R024](references.md#r024) [R026](references.md#r026) [R033](references.md#r033) 本文不把这些组成能力作为独立新颖性；技术差异在于将健康证据、跨后端完成语义、角色条件联邦查询、partial/coverage 收据与触发式现场统一起来。该差异目前属于系统设计，需要通过带标签故障的逐层消融证明其定位收益。

拓扑和并行策略决定同一局部事件的影响范围。TP、PP、DP、EP 的同步边界、超节点放置和 rank 映射共同决定通信距离、关键路径和空等资源量。因此，健康准入、通信调优和训练配置不能形成三套相互独立的判断；它们需要共享资产身份、软件版本、训练角色和时间坐标。

严格全局同步仍是当前训练基线，但并非唯一可能的同步组织。DiLoCo、Streaming DiLoCo 和 Decoupled DiLoCo 依次研究低频 outer synchronization、分片重叠和异步 quorum 聚合；Oobleck 与 TorchFT 则分别提供 pipeline 副本和框架内按 step 重配置的容错路径。[R020](references.md#r020) [R032](references.md#r032) [R030](references.md#r030) [R031](references.md#r031) Parameter Server 的版本、一致性和弹性状态管理只是候选 outer state plane。本文将这一组合视为待验证研究方向：其成立需要在模型质量、总计算、token accounting、goodput 和故障恢复方面与同步训练及其他候选实现完整对照，尚不属于当前项目实测结论。

## 已知限制

- 目标资源池的完整资产、软件版本和生产训练结果尚未全部导入，现有平台数字只对应已记录的 cohort 和实验条件。
- 同步长尾的部分机制证据来自不同计时边界；同一次 spike 的 CPU、runtime、驱动、设备与 collective 时间线仍需闭合。
- fleet-wide 观测的设计和局部实现证据较完整，但万 rank 端到端开销、查询延迟和丢弃率仍需目标规模实验。
- 变量 watch 与异常捕获已有实现证据，但不同 Python 版本、函数频率、设备同步副作用和 fatal signal 下的现场完整率仍需故障注入验证。
- 低通信弹性训练目前只有公开研究和系统设计依据，没有本项目模型、数据和故障注入结果。
- 当前没有与 Holmes、FLARE 同类的有标签定位准确率和诊断延迟结果，也没有与 MegaScale、FLARE 同类的目标规模观测开销曲线。

## 可复用资产

- 正确性、能力与前向进展三维健康证据模型；
- 拓扑感知通信、并行组映射和训练反事实方法；
- 本地事实、联邦查询、角色热力图、分布式火焰图、变量状态与崩溃现场组成的触发式诊断模型；
- 异步计时、零事件上界、异质事件率和同步放大的统计方法；
- 平台案例、实验索引、复现实验清单和版本化参考资料。
